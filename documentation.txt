--- OVERVIEW ---

Control system for the lifting mechanisms of a building layout model.
Architecture: one Master + several Slave devices.
Device-to-device link: ESP-NOW (WiFi channel 1, wireless).
Bluetooth is also supported for manual control.

Each Slave stores its settings in non-volatile memory (NVS) —
parameters survive a power cycle.

--- MASTER CONTROLLER ---

File: Areal Msater/src/Master.cpp

Main controller of the system. Receives commands and
forwards them to the right Slave devices over ESP-NOW.

Command input interfaces:
  - USB Serial (115200 baud)
  - Bluetooth: "Areal_Master"

Command sending:
  - 3 attempts per command, 50 ms pause between attempts
  - Waits for an acknowledgement (ACK) from the Slave

Motor command format:
  <target> <action>
  Examples: m2-1 up, m2-2 down, motors up

  Actions:
    up        raise
    down      lower
    stop      stop
    mode:sim  simultaneous movement mode
    mode:seq  sequential movement mode

Motor groups:
  motors      all motor Slaves at once

LED command format (reserved, NOT WORKING):
  <device> <effect>
  Examples: blue on, red off, all fill white

--- SLAVE: MOTOR 2 (m2-1) — LEFT MECHANISM ---

File: Areal motor 2 Slave/src/2-1 motor.cpp
NVS namespace: "slave2"

Drives two stepper motors in sync.
Both motors move together as a single mechanism.

Hardware:
  Motor 1: step=GPIO4, direction=GPIO2
           TMC2209 driver, UART: RX=16, TX=17
  Motor 2: step=GPIO18, direction=GPIO5
           TMC2209 driver, UART: RX=12, TX=13
  Limit switch (shared): GPIO15 (INPUT_PULLUP, NC — HIGH when triggered)
  AS5600 angle sensor: I2C (SDA=21, SCL=22)

Default motion parameters:
  Steps per move:  50,000
  Max speed:       3,000 steps/s
  Acceleration:    800 steps/s²
  TRIM range:      ±50,000 steps per motor

States (state machine):
  STATE_INIT        initialization and auto-homing
  STATE_IDLE        waiting for a command
  STATE_GOING_DOWN  lowering (both motors, down to the limit switch)
  STATE_GOING_UP    raising (both motors, by step count)
  STATE_ADJ         independent adjustment of a single motor

Homing (automatic on startup):
  1. If the limit switch is already pressed — both motors back off up by 2,000 steps
  2. Both motors move down simultaneously
  3. When the limit switch triggers — stop, position = 0

TRIM system (sync adjustment):
  If the motors stop at different heights, TRIM adds a
  permanent offset to the step count of a specific motor.
  Stored in NVS, not reset on reboot.

Commands (Serial / Bluetooth):
  0              emergency stop
  1              lower (DOWN)
  2              raise (UP)
  HOME           run homing manually
  M1:<N>         set steps for motor 1
  M2:<N>         set steps for motor 2
  TRIM1:<N>      permanent offset for motor 1 (saved)
  TRIM2:<N>      permanent offset for motor 2 (saved)
  ADJ1:<N>       temporary offset for motor 1 (not saved)
  ADJ2:<N>       temporary offset for motor 2 (not saved)
  SPD:<N>        set max speed (100–10,000)
  ACC:<N>        set acceleration (50–5,000)
  UART           check UART link with the TMC2209
  POS            show current positions of both motors
  RESET          reset to factory settings

Stored in NVS: moveStepsM1, moveStepsM2, trimM1, trimM2, maxSpeed, acceleration

--- SLAVE: MOTOR 4 (m4) — CENTER MECHANISM ---

File: Areal motor 4 Slave/src/4 motor.cpp
NVS namespace: "slave5"

Drives 5 stepper motors in a vertical stack.
The most complex controller in the system.

Motors (bottom to top):
  M5 (bottom): step=GPIO13, direction=GPIO12 | TB6600 | limit=GPIO23
  M4:          step=GPIO14, direction=GPIO27 | TB6600 | limit=GPIO22
  M3:          step=GPIO26, direction=GPIO25 | TB6600 | limit=GPIO32
  M2:          step=GPIO21, direction=GPIO15 | TMC2209 UART (RX=16, TX=17) | limit=GPIO33
  M1 (top):    step=GPIO2,  direction=GPIO4  | TMC2209 UART (RX=18, TX=19) | limit=GPIO5

Defaults:
  Steps per move:  50,000
  Max speed:       8,000 steps/s
  Acceleration:    600 steps/s²
  TMC2209 current: 800 mA, 16 microsteps

Operating modes:
  SIM (Simultaneous, default):
    All 5 motors move at the same time, in parallel.

  SEQ (Sequential):
    DOWN: M5 → M4 → M3 → M2 → M1 (one at a time)
    UP:   M1 → M2 → M3 → M4      (M5 does not take part in raising)

Homing (one motor at a time, bottom to top):
  1. M5 moves down to the limit switch → position = 0
  2. M4 does the same
  3. M3 does the same
  4. M2 does the same
  5. M1 does the same

Safety:
  M2 and above cannot be lowered while M1 is not yet raised.
  Limit switches are checked before every downward move.

Individual motor control:
  M<N>:UP            raise a single motor N (1–5)
  M<N>:DOWN          lower a single motor N (1–5)
  M<N>:ADJ:<steps>   temporary offset (+ up, − down)
  M<N>:S:<steps>     set steps for motor N
  M<N>:T:<trim>      permanent TRIM for motor N

Main commands (Serial / Bluetooth):
  0              emergency stop
  1              lower all (DOWN)
  2              raise all (UP)
  HOME           automatic homing
  TEST           test each motor (400 steps back and forth)
  MODE:SIM       switch to SIM mode
  MODE:SEQ       switch to SEQ mode
  SPD:<N>        max speed for all (global)
  ACC:<N>        acceleration for all (global)
  CURR:<mA>      TMC2209 current (100–2,000 mA)
  MSTEP:<N>      TMC2209 microsteps (1/2/4/8/16/32/64/128/256)
  TMCSTAT        TMC2209 driver status
  POS            positions of all 5 motors
  LIM            state of all 5 limit switches
  RESET          reset to factory settings

Stored in NVS: stp0–stp4 (steps), trm0–trm4 (trim),
               spd, acc, tmc_ma, tmc_ms, seqmode

--- SLAVE: MOTOR 1 (m1-1, m1-2) — SPARE ---

File: Areal motor 1 Slave/src/1 motor.cpp

Single stepper motor with homing.
m1-1 and m1-2 are currently not in active use.

Hardware:
  Step=GPIO4, direction=GPIO2
  TMC2209 driver, UART: RX=16, TX=17 (1 kOhm on TX)
  Limit switch: GPIO15 (INPUT_PULLUP, NC — HIGH when triggered)
  AS5600 sensor: I2C (SDA=21, SCL=22)
  Current: 800 mA, 16 microsteps

Defaults:
  Steps: 50,000
  Max speed: 3,000 steps/s
  Acceleration: 800 steps/s²

States:
  STATE_INIT         homing on startup
  STATE_IDLE         waiting
  STATE_GOING_DOWN   moving down (to the limit switch)
  STATE_GOING_UP     moving up (by steps)
  STATE_ERROR        error (limit switch not found)

Commands:
  0              stop
  1              down (DOWN)
  2              up (UP)
  HOME           run homing
  STEPS:<N>      set steps (100–500,000)
  SPD:<N>        speed (100–10,000)
  ACC:<N>        acceleration (50–5,000)
  ANG            read AS5600 angle (0–4,095)
  RESET          reset

Stored in NVS: moveSteps, maxSpeed, acceleration

--- SLAVE: LED (NOT WORKING) ---

File: Areal slave/src/Lights.cpp

! NOTE: LED control is currently NOT WORKING.
  The firmware is written and flashed, but integration with the Master
  and active control from the console are not implemented.

Hardware:
  NeoPixel strip: 3,700 pixels, GPIO5
  Color format: GRBW (800 kHz)
  Default brightness: 200 (out of 255)
  Device ID: "red" / "blue" / "yellow" / "orange"

Supported colors:
  white, red, green, blue, yellow, cyan, magenta,
  orange, purple, warm, off
  Or R,G,B,W comma-separated

Effects (implemented but not enabled):
  fill <color>                        fill the whole strip
  blink <color> <ms> <N>              blink N times
  breath <color> <steps> <ms>         smooth breathing
  wipe <color> <ms>                   wave fill
  chase <color> <tail> <ms>           running light
  sparkle <color> <N> <ms> <repeats>  sparkles
  strobe <color> <ms> <N>             strobe
  random                              building window simulation mode

Building window simulation mode (random):
  Simulates windows randomly switching on and off.
  Virtual windows: up to 200, spread along the strip.
  Day/night cycle: 10 minutes.
  Smooth transitions: fade in and fade out without delay().

Additional LED Slave commands:
  range <s> <e> [color]     fill a pixel range
  pixel <idx> <color>       set a single pixel
  brightness <0-255>        brightness
  status                    MAC, pixel count, current effect

--- ESP-NOW PROTOCOL ---

  Channel: WiFi channel 1
  Command format: <device>:<command>
  Example: "m2-1:2" (raise the left mechanism)
  Attempts: 3, pause between attempts: 50 ms
  Acknowledgement: ACK from each Slave
